# 从颜色按钮展开新主题

按用户要求，在0.1.29的一次提交主题基础上加入圆形揭示：点击浅色、深色或跟随系统，实际明暗发生变化时，以该按钮当前布局的中心为圆心，约400ms展开新主题，半径覆盖最远角落。跟随系统解析后的明暗相同则只更新选项。

## 绘制与中断

- 新增`ThemeRevealHost`，仅在需要变化时记录当前合成画面，并用Compose 1.7.6的`GraphicsLayer.toImageBitmap()`保留临时旧画面。主题一次提交，下面绘制新画面，旧画面按不断扩大的圆形缺口裁切；不重建逐帧ColorScheme，不把动画时钟传给页面排版。
- 截图仅在内存中使用，不写入文件、不申请截屏权限。完成、页面切换、尺寸变化、退到后台或宿主销毁时释放覆盖引用和捕获层的子图层引用。捕获失败或超时仍直接保存并切换主题，不能让外观功能阻止设置落盘。
- 连续反向选择从当前合成画面重新取帧；最后一次选择覆盖尚未提交的旧选择。同色选择不额外截取、不重播；捕获尚未完成时点回原选项也能撤销待提交的变化。
- 按钮继续使用固定图标占位、绘制阶段的本地弹簧、按压与ripple。圆形揭示不阻断页面触摸；导航变化清除旧页面覆盖图。系统栏图标在圆形到达各自位置时切换，系统关闭动画时直接更新。

依据为本项目固定版本的Compose ui-graphics 1.7.6源码及[官方图层记录说明](https://developer.android.com/develop/ui/compose/graphics/draw/modifiers#write-contents-of-composable-to-bitmap)。Android 9及以上走硬件Bitmap，Android 8沿用该库自身兼容捕获路径；没有升级依赖。

## 验证范围

主机Layoutlib回放直接使用生产`ThemeRevealState`、`ColorModeCard`和动画时钟，不手工指定进度。由于Layoutlib不是手机GPU，快照适配器提供上一张真实渲染帧，不能把它当成真机硬件捕获或帧率实测。检查浅→深、深→浅、浅→同色系统、连续三次反向切换和中途取消；对靠近圆心及远角的像素先后变化、约400ms覆盖、最终偏好及页面重组次数设断言，并保存原生APNG。

保留原有A/B回放，继续约束根部没有逐帧页面重组。所有预览适配器仅属于preview测试源集。29项JVM和21项设备测试预算不变；设备测试仅编译，不使用安卓模拟器，不代发真实AI请求。真机GPU快照、触控延迟及物理帧率仍待手机验收。
