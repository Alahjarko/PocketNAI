# 本机 MCP（2026-11-13）

PocketNAI 可以在用户需要时，作为同一部手机上其他 AI 助手的生图工具。首版面向 RikkaHub 的 Streamable HTTP 客户端，范围是单张静态文生图、任务查询与图片预览；Gemini 原生协议、技能导入、参考图和局部重绘工具另行开发。

## 使用

1. 在设置中打开「本机助手连接」。默认需要逐张确认；如需让已配对助手直接生图，先开启「本次连接直接生成」，再点击「开启连接」。开启直接生成意味着授权本次连接产生图片服务费用。
2. 在 RikkaHub 添加 **Streamable HTTP** 类型的 MCP 服务，地址填 `http://127.0.0.1:47761/mcp`。
3. 添加请求头 `Authorization`。回到 PocketNAI 点击「复制认证值」，粘贴为请求头的值；复制内容已包含 `Bearer `，不要重复添加。
4. 在 RikkaHub 当前助手中启用该服务的工具。先获取能力，再提交任务；默认模式下回到 PocketNAI 核对参数和报价，点击「确认生成 1 张」。
5. 助手查询原任务直至完成，再取回图片。完整原图保存在 PocketNAI 画廊。用完点击「停止连接」。下次开启无需重新配对；只有重置连接令牌后需要更新客户端认证值。

只监听 IPv4 回环地址，不开放局域网。固定端口被占用时提示启动失败，不悄悄换端口。锁屏会关闭监听；没有任务执行且 20 分钟无有效请求也会关闭。服务不随开机启动、不自动重启，不承诺长时间锁屏保活。

## 工具与兼容

| 工具 | 用途 |
|---|---|
| `get_image_capabilities` | 支持的提供商、模型和参数取值；不返回密钥、当前草稿或历史图片 |
| `submit_image_task` | 提交一份单张文生图，立即返回 `job_id` 与状态；必须提供稳定唯一的 `request_id` |
| `get_image_task` | 查询原任务；可用 `wait_seconds` 等待 0–20 秒的状态变化 |
| `get_image_result` | 取回该任务产生的图片，返回 MCP `ImageContent` |
| `cancel_image_task` | 取消尚未发送的任务，已发送的请求不取消或补发 |

`request_id` 为 8–128 个 ASCII 字母、数字、下划线或短横线。客户端因超时重试工具调用时必须复用原值和参数；相同值配不同参数会被拒绝。请求记录永久保留用于去重，界面展示最近 40 个已结束任务及全部未结束任务，不因界面截断而失去去重能力。未结束任务最多 4 个，每次只执行一个。

NovelAI 支持 `prompt`、`negative_prompt`、`model`、`width`、`height`、`seed`，复用绘伴单张工具的参数规则；未指定的步数、采样等采用提交时设置，完整提示词不重复追加质量标签，不附加当前参考图或首页角色配置。OpenAI 支持 `prompt`、`model`、`size`、`quality`，固定单张 PNG，不附加当前参考图。未知参数拒绝，不静默反射到上游请求；所有提供商均复用现有参数验证、SFW、共享生成锁、文件存储和计费链路，不覆盖首页草稿。

NovelAI 在确认和发送前复核当前账号、SFW 与报价；逐张确认模式下报价变化回到待确认。OpenAI 复核独立密钥及 SFW，明确提示按实际用量计费、生成前金额无法确定，不把它混入 Anlas。直接生成仅属于当前连接，重开默认关闭。

提供 JSON 响应形式的 Streamable HTTP，协商 `2025-03-26`、`2025-06-18` 或 `2025-11-25` 版本。初始化、通知、ping、工具列表与调用均有实现；不使用长时间 SSE 连接，也不把整个生图过程塞在一个工具调用里。认证后的 GET 返回 405；不宣称支持后续不同握手的协议版本。返回预览最长边 1536 像素、JPEG，原图保留在画廊；不提供任意文件路径或图库遍历工具。

## 生命周期与请求边界

- 用户在前台启动 `specialUse` 前台服务，显示可停止的持续通知。空闲时不持有唤醒锁；实际生图执行时沿用短时、可续期唤醒保护。
- 任务属于进程中的管理器，与单个 HTTP 调用分离。关闭连接、客户端断开、工具超时均不重发图片 POST。已发送的任务继续尽力保存，之后重新开启服务，用原 `job_id` 查询和取图。
- 停止后拒绝新发送，尚未发送的确认任务取消。重开监听不会撤销旧任务的去重记录，也不会恢复它的发送。
- 每个任务使用 `AtomicFile` 保存到私有 `files/mcp-jobs/`，发送前先写入执行状态。进程重启后未发送项取消、执行项标记结果待核对，均不补发；已有图片 ID 仍可查询。记录损坏时同一请求编号保持保留，不能当成新请求发送。
- 配对令牌用独立 Keystore alias 加密保存，备份排除令牌首选项和 MCP 任务目录。只有用户主动点击才复制配对值；不复制 NovelAI、OpenAI 或 LLM 服务密钥，不在任务、返回值或日志里保存它们。
- 校验 Host、Origin、Bearer 认证、请求路径、内容类型与长度；请求体上限 128 KiB，不落 HTTP 临时文件。线程池有上限，错误不反射原始请求或异常内容。
- 不修改 Room schema，不卸载应用、不清历史、不更换已有签名。NanoHTTPD 2.3.1 的 BSD 许可随 APK 资产分发。

## 验证入口

JVM 协议验收扩展既有 `ChatProtocolTest`，覆盖版本、通知和工具协议。设备端在既有后台启动回归中调用 `McpTransportAcceptance`，用隔离凭据和文件、真实回环 socket、假生图后端验证认证、输入边界、去重、确认、发送前报价变化、断线重连和图片返回。测试数量仍为 29 项 JVM + 21 项 Android。

`-PlocalMcpBenchmark=true` 构建独立包 `net.pocketnai.mcpbench`，复用生产连接页面与服务，生图仅产生带「MCP OK」的本地几何图。它另开 `127.0.0.1:47762/v1` 的假 OpenAI 聊天接口，供 RikkaHub 的真实客户端按提交、查询、取图顺序联调；测试模型为 `gpt-4o-mini`，密钥使用任意测试值。这个包不构造生产 `AppContainer`、不读取上游凭据，不进入普通 APK。其 `INTERNET` 权限只用于本机 socket，不能误套旧画廊夹具的无网络权限断言。

## 本轮结果

- 生产源码 `0511aad`：29 项 JVM、21 项 Android 回归全部通过；此前先跑生成链路与 MCP 所在后台回归共 8 项，也通过。注册预算保持 50 项。原位 `install -r` 安装 Debug、测试包及 R8 优化包，无卸载、清数据或数据库变更；旧图库仍可浏览。
- 独立夹具源码 `8597d2b`：只修正夹具编译，生产代码与上述已测提交相同。R8 夹具与正式 R8 包均构建成功，普通 APK 中不含夹具入口和假聊天服务，包含 NanoHTTPD 许可。
- 实际安装官方 [RikkaHub 3.2.0 ARM64 APK](https://github.com/rikkahub/rikkahub/releases/tag/3.2.0)，通过真实配置页面连接，读出全部 5 个工具；真实客户端依次调用 `submit_image_task → get_image_task → get_image_result`，其对话中显示本地「MCP OK」图片。首次流程生成调用计数为 1。
- 逐张确认模式下，确认前计数不变；人工确认才执行。锁屏样本约 0.85 秒后关闭回环监听，已发送任务继续持有前台保护并保存，完成后服务退出。设备空闲时 `Wake Locks: size=0`；所见标签是已释放的历史记录，不能把历史标签误算为仍持有。
- 重新开启后，在 RikkaHub 重放相同的稳定请求编号，直接取回原结果；实际阶段为 `submit_image_task → get_image_result → done`，生图计数前后相同。这里验证的是相同请求的重放，不能据此把用户主动要求的新一张图也复用同一编号。
- 正式应用通过实际设置项进入、返回和通知点击进入页面；1.35 倍字号下核对上部操作及滚动后的复制／重置区。通知权限、字号及屏幕超时全部恢复；测试服务和假接口进程已关闭。
- 全程不发送真实 LLM、搜索或生图请求。RikkaHub 联调只配本机假聊天模型；没有配置其快速标题模型，自动标题提示不作为 PocketNAI 工具失败。真实提供商的参数、文件和费用链路依靠既有假 API 回归与代码复核，没有用真实计费请求代验。

验收环境是用户授权的既有云端 Android 14，720×1280，原系统支持 ARM 原生桥。系统曾出现 `lmkd epoll_wait errno=22` 和一次外部请求短暂不可达，原位重启故障服务后继续，未以改应用代码掩盖环境问题。测试计数器仅在当前夹具进程内累加，跨进程时不把它当作全局累计量；实际重连断言比较同一进程中的调用增量与持久化任务状态。

本地证据目录：工作区上层 `artifacts/local-mcp-2026-11-13/`，包含完整日志、JVM XML、原生截图、联调阶段及状态 JSON、复现脚本和 APK。2026-11-13 经用户授权，code 39 / `0.1.39` 已同步 master，并以原公开签名发布 [build-39](https://github.com/Alahjarko/PocketNAI/releases/tag/build-39)。正式 APK 与该无签名候选的全部编译内容相同；设备包仍沿用云端测试签名，不作为正式附件。见[发布核对](release-0.1.39.md)。
