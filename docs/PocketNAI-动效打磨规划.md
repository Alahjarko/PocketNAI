# PocketNAI 动效打磨规划

日期：2026-10-08 · 状态：往返与底栏修正 v0.4

本轮完成现有源码盘点和实施规划。尚未修改应用代码、录制新的动效对照或测量当前帧率。下文时长为样机调参起点，性能数字为候选验收目标，不是已经达到的结果。

## 1. 希望达到的使用感

PocketNAI 的主要活动是编辑提示词、生成、看图、挑图和聊天。动效应让这些活动连接得更自然：手指拖动有回应，图片切换有连续性，操作完成有反馈，长时间浏览不会感到界面一直在动。

方向调整为**优雅、流畅、简约、有视觉吸引力，以空间连续性为主线**：

- 界面控件使用主题内的纯色与必要的透明度，不加入渐变色、彩色光晕或emoji。作品本身保留原有颜色。
- 图片的“渐变展示”指透明度淡入，不给作品叠加渐变色。成功对勾用矢量路径绘制，不使用emoji字符。

- 页面、弹层和按钮采用一致的节奏；快进快出，避免每个组件各自弹跳。
- 用户主动打开或切换内容时才出现明显过渡。滚动经过的旧图片、旧消息不重复播放入场。
- 操作逻辑立即响应，动效负责呈现结果，不等待动效结束才收藏、切换或提交。
- 长提示词、思考过程和流式正文维持稳定排版；避免整块内容在每次变长时缓慢伸缩。
- 常用按钮的位置保持稳定。保留生成按钮在悬浮层头部、详情操作在长提示词之前的布局。

首轮主线改为：**发起生成 → 占位让旧图平滑让位 → 非线性进度环 → 完成并原位成图 → 图片从卡片展开 → 返回当前来源位置**。悬浮层跟手、双击缩放等继续保留，按主线基础完成后安排。

## 2. 当前实现盘点

以下是2026-10-08源码观察，不代表设备上已经复现了卡顿。

| 区域 | 当前实现 | 本轮关注点 |

## 3. 统一节奏与动效范围

先建立少量共用参数，按首轮样机手感调整后再推广。以下均为建议初值。

| 类别 | 初始范围 | 适用位置 |
|---|---|---|
| 即时反馈 | 80～120ms | 收藏图标、选中描边、展开箭头 |
| 内容淡入/替换 | 140～180ms | 附件条、简短状态、图片加载完成 |
| 页面与弹层 | 180～240ms进入，120～180ms退出 | 详情、画师库、阅读器等层级变化 |
| 图片双击缩放 | 220～280ms | 1倍与2.5倍之间的缩放和平移 |
| 来源展开/收回 | 260～340ms展开，220～300ms收回 | 图片卡片与详情/预览的连续边界变化 |
| 卡片让位 | 220～300ms | 新任务插入时可见旧卡片平移到新位置 |
| 手势跟随 | 不叠加补间延迟 | 头部拖动、捏合、放大后平移 |
| 松手落定 | 以约180～260ms的手感为调参方向 | 悬浮层回到展开/收起锚点；弹簧参数实际时长需测量 |

非手势过渡优先使用温和加减速。弹簧只用于需要连续速度的落定过程，采用低回弹或无明显回弹的设置；不把弹簧参数直接当作固定毫秒数。

状态反馈保持轻量；图片展开则明确沿来源边界放大，参数与文字独立进入，不跟着整页拉伸。Material已经提供的点击波纹、按压和默认弹层效果先复用，避免出现两套效果叠加。

透明度动画不会自动移除布局和语义；隐藏的内容还需同步处理点击、焦点和无障碍可见性。实现时按组件生命周期选择AnimatedVisibility或绘制层变化，见[Compose动效指南](https://developer.android.com/develop/ui/compose/animation/quick-guide)。

## 4. 重点场景设计

### 4.0 生成过程：视觉进度、完成对勾与原位揭图

用户已明确希望使用流畅的模拟进度。单张生成采用**视觉型进度环**，与服务器进度、批次完成计数分开；不显示虚构的百分比或剩余秒数。

| 呈现状态 | 动效 | 状态依据 |
|---|---|---|
| 任务开始 | 同比例占位进入队列，旧图平滑让位；圆环从零开始 | 原有流程已经创建该任务，不由动效额外发请求 |
| 生成中 | 单色粗圆环先明显前进、随后自然放缓，保持连续变化 | 根据经过时间模拟视觉节奏，最高保持在约90%～95% |
| 超过预估时长 | 环尾可缓慢流动，保持“生成中/等待结果”状态，不倒退或重新开始 | 尚未拿到可显示的结果 |
| 结果可显示 | 当前环补到满，起始建议140～180ms | 本地成图已提交且显示资源准备好 |
| 完成确认 | 环形收束成矢量对勾，起始建议120～160ms | 成功状态确认，不作为发请求或改数据库的触发器 |
| 揭图 | 对勾退场，成图在同一槽位以180～220ms透明度淡入 | 显示的就是这个任务的结果，保留原宽高比 |

完成对勾和揭图后半程适度重叠，成功到成图可见的额外呈现时间先控制在约350～450ms，样机再调整。快速返回的任务直接收尾，不为完整播放动画刻意延长等待。

视觉建议：圆环直径约48～64dp、线宽约5～6dp、圆润端点，主题单色配低对比轨道。重点在速度曲线和形态衔接，先不加入额外呼吸、发光、彩色变化或持续装饰旋转。

边界必须清楚：

- 模拟进度可以改善等待节奏，但满环和对勾只在真实结果可显示后出现。不能先宣布成功，再继续等网络或解码。
- 真实流式进度可辅助调整速度，但不能让可见进度来回跳动，也不能把最后一个采样步等同于本地图片已经可用。
- 失败、超时待确认或图片加载失败时停止成功序列，呈现对应状态。动画不自动重发请求，也不清掉待确认记录。
- 以任务ID统一持有视觉状态。切页或回到前台不会把同一任务从零重播；已经完成的旧图片直接显示。
- 当前可见任务卡承载主要等待反馈；生成按钮保留忙碌/禁重入语义，不让两个强烈的进度动画同时争夺注意力。任务卡被面板遮住时，头部可提供必要的轻量反馈。
- 单次多张按预计产物数量预留槽位，槽位共享请求进度，按实际返回的图片序号收尾。展示数量不增加请求次数；缺失结果不能用假图补齐。

**通过条件：**进度不中断、不回退；真正完成才变勾；原位出现正确成图；失败不展示成功；切页不重播。

### 4.1 首页生成悬浮层：先做可对照样机

**目标：抬手、松手和面板移动之间有连续关系，内容滚动仍然安全。**

准备两种小范围方案，优先评估第二种：

1. 保留现有松手切换方式，统一展开/收起节奏与箭头过渡，作为低风险对照。
2. 只在头部拖动时提供连续的面板位移反馈；松手仍按48dp净位移门槛判断是否切换稳定状态，未达门槛回到原锚点。

连续方案需先验证现有Material组件的公开接口能否承载。若需要自定义布局或更换状态管理，先限制在这个组件内做样机，不直接改造整个首页。

必须保留的行为：

- 内容区的拖动、惯性和边缘剩余位移不推动面板；不重新启用整层滑动。
- 不用短促高速度甩动绕过48dp门槛。
- 手势中断回到可解释的稳定位置；新的拖动可以接管正在进行的落定动画。
- 收起/展开过程中不卸载内部滚动，重新打开仍在原编辑位置。
- 正在生成时保留现有收起行为；用户再次展开与生成状态变化不能争抢位置控制。
- 点击把手、箭头和无障碍按钮都能完成相同操作，不能只提供拖动入口。

**样机通过条件：**在表单顶部/底部滚动均无误收起；短拖不切换；连续拖动和快速反向操作不突跳；原滚动位置保留。

### 4.2 画廊重排与“从哪来回哪去”

#### 4.2.1 新任务在连续瀑布流中占据空间

这是排布与动效共同完成的改动，不能只给现有占位加一个入场效果。

原来的生成占位在日期分组之前，紧接着的日期标题横跨整行，会阻止旧图片自然占据占位旁边的位置。首轮改为任务与所有图片共同参与连续瀑布流：保留顶部日期标题，后续日期只在该日期第一张图片的角标中显示。日期分组数据与排序保留，但不再用整行标题截断列位。跨日期新增任务时，旧第一张也能自然挪到旁边。

- 新任务按真实目标尺寸占位，优先用`params.targetSize`，而非一律方形，减少成图后第二次整体重排。
- 槽位的呈现身份在等待、完成对勾和成图之间连续，可采用生成ID与图片序号绑定；数据库imageId与历史记录不改名。
- 生成记录与图片Flow到达顺序不同时，保留原槽位直到成图可呈现。避免先移走占位、下一帧又插入新图片。
- 更新时计算旧、新位置，可见旧图片平移到新的列位；保持图片尺寸比例，不把图片本身压扁或拉长。
- 最终排布可以重算，动画只覆盖视口及小范围缓冲区。离屏几百张图片直接采用新位置，不逐张建立动画。
- 用户就在列表顶部时，可以完整看到让位；用户正在回看下方时，保留可见锚点，不因新任务或新成图把列表拽回顶部。
- 日期分组、只看收藏、搜索及多选继续有一致语义。任务不匹配当前筛选时，保留现有隐藏规则，不塞入“仅收藏”等结果中。

横竖图没有统一的“行高”。“第一位到第二位”表示排序关系，实际终点还取决于下一可用列的高度。假设同宽下竖图高度约等于两张横图与间距之和：

| 队列 | 左列 | 右列 |
|---|---|---|
| 插入前：A竖、B横、C横 | A竖 | B横，下面接C横 |
| 插入后：任务竖、A竖、B横、C横 | 任务竖，下面接B横 | A竖，下面接C横 |

实际比例与间距按元数据计算，不能硬把任意两张横图凑成一张竖图。保留紧凑瀑布流；如果样机显示跨列轨迹过于绕动，先调整有限的可见项目节奏和层叠顺序，不急着换成等高网格。

本地Foundation `1.7.6` 的瀑布流项目作用域已核对存在`animateItem`入口，优先验证现有懒加载排布动画的效果。若其列位变化不能满足连续顺序与稳定锚点，再评估局部自定义排布，不在规划阶段承诺现成API已经解决全部轨迹问题。

#### 4.2.2 图片沿实际来源展开与收回

共享图片过渡提升为首轮核心能力。打开时由卡片的当前边界扩大到详情图片区域，背景和参数区随阶段进入；返回时根据来源容器中的当前位置收回。图片身份匹配、公共过渡作用域与裁切处理参考[官方共享元素说明](https://developer.android.com/develop/ui/compose/animation/shared-elements)。

呈现层需要一份轻量来源记录：来源页面/弹层上下文、图片ID、当前边界与裁切/圆角、列表滚动锚点。它仅用于UI，不写入生成历史或PNG元数据。

- 打开位置来自当次实际测量，不能写死为屏幕中心或某个序号。
- 返回重新定位同一图片，重新测量终点。后台新图、收藏排序、旋转和窗口尺寸变化后，不能沿用打开时的旧矩形。
- 详情从A滑到B后返回，优先收回到来源列表中的B；仍回到原来源上下文，不把B硬缩进A的缩略图。
- B尚在来源列表但离屏时，先在遮挡层下定位它，待目标布局就绪再开始收回；不能长距离飞向屏幕外一个猜测的矩形。
- 图片被删除或不再匹配原筛选时，保留原筛选与列表状态，使用短退场回到来源容器，不冒用其它图片做收回终点。
- 图片从Crop到Fit的变化需连续处理。参数文字在展开后半段独立进入，不随图片被拉伸；禁止再叠加一层整页缩放或重复淡入。
- 缩略图与大图解码交接保持旧画面，资源就绪后替换，不闪黑、不同时长期保留两张全分辨率位图。
- 展开未完成就返回时，沿当前呈现状态反向收回，不先跳到完全展开态。

#### 4.2.3 把来源原则推广到合适的区域

| 场景 | 来源与返回目标 |
|---|---|
| 首页图片 → 详情 | 当前画廊卡片与其所在日期组/滚动位置 |
| 抽卡结果 → 详情 | 对应批次的结果卡片，保留批次、筛选和滚动位置 |
| 画师串收藏 → 大图/详情 | 原收藏卡片与当前选中的同串图片，保留搜索、列表位置和来源层 |
| 聊天图片/附件 → 查看 | 原消息或输入框附件；关闭后不改动聊天跟随状态 |
| 参考图预览 → 查看 | 原参考槽位，编辑内容与焦点按场景恢复 |

“同一份内容展开”适合使用来源形变；普通菜单、权限页和整个设置页不需要把小图标放大成大窗口，使用统一方向与层级节奏即可。

现有若干预览使用原生`Dialog`独立窗口；画师串收藏进入详情还会先关闭来源弹层。要做到完整往返，需要协调来源保存、返回恢复与过渡宿主，可能把图片预览的呈现层收口到同一宿主中。不是仅在NavHost外包一个动画就自然覆盖全部窗口。先完成画廊到详情，再推广这些层级，不重写生成与存储链路。

全屏双击缩放继续按上一版要求完善：倍率和平移同步变化，围绕点按位置缩放，新捏合/平移立即接管，每帧遵守边缘约束，缩回1倍平移归零。

**通过条件：**旧图自然让位且比例不变；成图在原槽位出现；打开和返回都对应正确图片的当前位置；更换详情图片、删除、筛选、旋转和中途返回有明确退路。

### 4.3 提示词、独立角色与折叠区：区别操作与输入

- 点击展开/收起、添加/移除角色属于主动结构变化，可使用短过渡。
- 打字、中文组合输入、选区变化、自动换行属于持续编辑，不驱动整个角色区的高度动画。
- 展开箭头统一旋转反馈；短说明区域可以轻微展开，长输入内容优先自然布局或轻淡入。
- 标签建议仅在建议容器出现/消失时做过渡，查询结果每次变化不逐个弹出标签。
- 切换参考图页签只改变可见面板，不清空已有挂图；不在切换动画中产生额外导入、编码或请求。
- 角色位置标记可以有短位移反馈，真实x/y参数在操作时更新，不等动画结束才写入。

**通过条件：**光标、中文组合文本、提示词权重底纹不漂移；手指编辑时界面不持续伸缩；折叠不清空输入。

### 4.4 聊天：优先消除抢滚动与结束闪动

保留现有长文和流式显示策略：超过2000字才折叠，预览最多1800字，流式显示最近2400字，全文独立分段阅读。先不调整这些阈值。

- 发送自己的新消息和首个助手气泡可有轻淡入；同一气泡后续token增长不重复入场。
- 关注当前`partial`条目转成正式历史条目时key变化：呈现层保持一次回复的连续身份，避免再次入场或滚动重置；不改动原始工具ID、思考和存储协议。
- 保留约120ms的流式界面提交节流与单协程跟随。用户回看时不被新文字、图片、工具卡强拉到底部。
- “回到最新”保持一次明确的滚动操作，不给每个token建立新的滚动动画。
- 思考区打开只影响该条消息；长思考依旧进入分段阅读器，不动画展开数万字内容。
- 附件添加/移除在输入框附近做短过渡，不让整个对话列表随附件高度弹跳。
- 键盘避让继续由外层Scaffold统一负责，跟随系统Insets；不再叠加一个自算键盘高度动画。导航栏的显示变化需与键盘一起协调。
- 生成确认卡与生成结果图按真实状态切换，按钮和报价立即可读，不用动效暗示已经生成成功。

**通过条件：**普通回复完整可见；长回复完成时不闪动；手动回看不被抢滚动；键盘上方不出现重复留白；图片确认仍只授权既有范围内的请求。

### 4.5 抽卡、画师库和画师串收藏：控制同时发生的变化

- 新结果只让新卡片短淡入，旧结果不重播；用户回看其它位置时不自动跳回顶部。
- 星标图标即时反馈。若收藏置顶改变顺序，保持当前可见项目的锚点；最多让相关可见卡片移动，不给千条结果统一播放重排。
- 画师库启用/移出、搜索和批次切换用容器级短反馈，不逐卡串联入场，也不为每张代表作重复建立无限动画。
- 收藏卡片进入大图预览先统一弹层节奏；同串缩略图切换时先保留选中描边，图片采用轻替换，避免旧、新两张全分辨率图长期叠加。
- 批次进度按实际成功/失败计数显示。当前单张可以使用4.0的视觉进度环，不能据此伪造批次完成数；不增加抽奖转盘、卡包翻面或逐张庆祝。
- 清理完成呈现一次清晰结果。图片删除范围和收藏判断仍由现有事务负责，退出动画不能先行假定删除成功。
- 应用退到后台时停止可见动效，已确认抽卡的前台服务继续工作；页面动效不改变后台生命周期和请求间隔。

**通过条件：**新增、收藏、搜索与清理时浏览位置可预测；大量结果下没有成批闪动；后台抽卡行为保持不变。

### 4.6 导航、设置、弹层与重绘工具

- Tab切换采用轻淡入，保持每个页面自己的滚动和草稿；不为“画廊→设置”伪造左右空间关系。
- 图片详情与预览采用4.2的来源展开/收回，不叠加第二套整页转场；阅读器等其它深一层页面采用短进退。打开多个弹层时明确谁在最上层，退出回到原上下文。
- AlertDialog、DropdownMenu等Material组件先保留默认机制，只统一必要参数或内容切换。避免平台窗口动画与内容位移动画重复。
- 系统Photo Picker、安装器、权限页使用系统行为，不模拟第二套转场。
- 重绘的画笔、橡皮与笔触直接跟手，不能为笔触补间增加延迟；仅工具选中和工具栏开关参与动效打磨。
- 返回手势与可打断退出放在导航稳定之后核对，不能为了退出效果拦住正常返回或让用户丢掉草稿。

## 5. 动效实现边界与性能策略

### 5.1 轻量公共入口

建议新增一个小的`ui/motion/PocketMotion.kt`，集中时长、缓动、是否减少动效等策略；来源记录与统一图片过渡宿主按4.2的实际需要增设。它们管理呈现身份、边界和层级，不承担网络、生成或数据库职责。只有确实重复的行为再提取辅助函数。

优先级顺序：Material/Compose已有机制 → 小范围参数统一 → 明确必要的自定义手势。图片库、导航库和数据层不为动效一起重写。

### 5.2 动画只读取必要状态

位移、透明度和图片缩放尽量在布局/绘制阶段读取动画值，不把每帧值一路传到整页，让长列表和长文本重复组合。涉及真实占位尺寸的变化仍需布局处理，不能单纯移动绘制位置而留下错误的点击区域。依据[Compose性能实践](https://developer.android.com/develop/ui/compose/performance/bestpractices)与[动效性能说明](https://developer.android.com/develop/ui/compose/animation/quick-guide#optimize-animation-performance)。

保留稳定key与懒加载，测量后再决定是否需要拆分重组范围、缩小订阅或缓存派生列表。不能把所有慢帧都归因于动画，也不能用淡出隐藏图片解码、文本布局或数据投影的耗时。

### 5.3 生命周期与中断

同一个位置/倍率由一个控制入口负责。新操作以当前帧值为起点，中断旧动画，不从固定初值重新开始。用户已离开的页面不维持装饰循环。

动画完成回调不承载生成、重试、删除、保存或费用判断。操作次数与业务权限继续由现有ViewModel、仓库和事务控制。

### 5.4 减少动效与布局适配

核对系统动画时长缩放为0或缩短时的行为；Compose/Material已有响应先保留，自定义方案必须同样正确落定。应用层“减少动效”开关作为可选后续项，不先增加设置负担。

减少动效时直接呈现最终状态，保留点击、键盘和捏合能力，不能留下透明但能点击的层。窄屏、横屏、宽屏分栏及大字体分别检查；宽屏常驻生成面板不套用手机悬浮层动画。

## 6. 分阶段交付

| 阶段 | 范围 | 可见交付 | 进入下一阶段的条件 |
|---|---|---|---|
| 0：盘点与基线 | 核对源码、设备和3条核心使用路径 | 本规划；后续补短录屏与同条件性能基线 | 能区分当前问题、已有能力和待尝试方案 |

| 2：推广来源连续性 | 抽卡结果、收藏预览、聊天附件、参考槽位与全屏缩放 | 多个来源都能自然往返，保留来源层及浏览状态 | 图像解码衔接、来源恢复、分页后返回和不可用来源的退场稳定 |
| 3：聊天与编辑 | 悬浮层跟手、输入区、附件、流式结束、思考/长文阅读、角色折叠 | 长内容下仍稳定的交互版本 | 不抢滚动、不误收起、不重播回复、不破坏组合输入 |

每阶段控制改动范围，保留能单独回退的参数或组件改动。手感尚未确定的样机先本地验收，不把所有阶段捆成一次大改。这里不承诺日历工期；自定义悬浮层与图片共享过渡的兼容结果会直接影响工作量。

## 7. 验收方式：少量真实路径，避免测试再膨胀

只维护三条动效体验路径，按阶段选用，必要时在相同条件下重复对照：

1. **编辑与生成入口：**长提示词、角色折叠、内容滚动、头部拖动、键盘和反向操作。自动化只使用本地状态或假API，不代发真实生成。
2. **生成呈现、看图与抽卡：**占位插入与横竖图让位、快慢返回/失败的进度环、原位揭图、动态来源展开与收回、双击/捏合和收藏预览；100张结果做日常路径，1000条结果作压力档，万条只在发现规模瓶颈时补测。任务结果由受控假API或隔离呈现状态提供，不代发真实请求。
3. **聊天：**普通回复、长文/长思考、流式结束、手动回看、附件与键盘。保留约30万字历史量级作为压力参考，数据限于临时隔离状态，不写用户主库。

首轮以同一设备、同一刷新率、同一编译模式和相同数据对比。当前交付包是debug配置，不能把其测量结果直接推广为所有手机或未来release配置的表现。

录屏用于判断顺序、跟手和闪动；截图用于确认稳定状态。帧耗时优先用适用于Compose的本地性能跟踪；跨Dialog需采样实际窗口，不能只记录底层Activity。必要时用Perfetto的FrameTimeline定位，参考[Android渲染诊断](https://developer.android.com/topic/performance/issues/render#tracking-jank)。

候选验收目标：

- 高频点击的逻辑响应不等待动画结束；可见状态与真实操作状态一致。
- 新增动效不造成稳定场景P95帧耗时相对基线明显恶化；先以不超过约10%的变化作为排查门槛，结合慢帧分布和主观感受判断，不把单次波动当成失败。
- 以实际刷新周期判断慢帧：60Hz约16.7ms、120Hz约8.3ms；同步记录连续掉帧与超过100ms的停顿，不能只报告平均FPS。
- 快速重复点击、反向拖动、返回或旋转，不留下卡在半途的面板、错误图片或重复动作。
- 减少/关闭动画时功能仍完整，内容区滚动不误触面板，输入选区与草稿保留。

JVM与设备测试总数继续不超过50项，当前源码清单为49项。优先复用或替换现有关键手势回归，不为时长常量、曲线和每个淡入效果增加测试；性能对照不恢复已删除的大批截图夹具。现有规则见[验证专题](development/verification.md)。

## 8. 首轮明确先不做的内容

以下效果暂不进入首轮，因为收益与风险尚不匹配：全页毛玻璃/实时模糊、每张卡片串联入场、长期呼吸/闪烁装饰、抽卡翻牌与逐张庆祝、长文字高度逐token补间、统一套用大幅弹跳。渐变色控件、彩色光晕与emoji不纳入本轮设计。

首轮也不改变长文折叠阈值、画师名单、生成参数、数据库结构、费用或请求规则。任何后续发现的功能问题单独列出，不混入动效样机悄悄处理。

## 9. 首轮实现与验收（2026-10-08）

三类交互独立触发，不要求用户串行完成同一套演出：生成时看进度环，新增任务时让位，打开/返回图片时展开与收回。

已实现：

- 连续瀑布流中插入按目标画幅占位的任务卡片，可见图片以280ms移动让位。后续日期采用图片角标，跨日期也连续排布。
- 任务与成图使用同一槽位；视觉进度非线性前进，最多93%，实际图片解码成功后补满160ms、转勾150ms，短暂停留70ms，再以220ms揭图。旧历史不重播完成动画；不确定/失败结果不会转勾。
- 图片共享边界过渡300ms，按实时布局展开和收回。详情支持从当前页返回对应画廊图片；点击后的异步加载使用来源缩略图，消除空白段。
- 共享图片复用于聊天生成图与抽卡主列表；系统Dialog中的图片历史和画师串收藏预览仍沿用原行为。

验证：32项 JVM、18项设备测试全绿，总数50。新增仅一项隔离的设备动效流程检查，使用本地几何图片，不读取账号，不写用户历史，不调用真实生成。MuMu实际画廊使用已有图片确认展开、详情横滑与返回，截图和录屏保存在 `.tooling/motion/`。原签名code14、版本名 `0.1.14-motion` 本地APK覆盖安装成功，未发布GitHub。

性能记录：最终连续画廊版本在MuMu两张已有图片之间连续五次展开、横滑、返回，关闭录屏/截图后采集879帧，P50 5ms、P95 21ms、P99 121ms，系统报告49个卡顿帧（5.57%）。跨日期排布修订前，含首次载入和录屏/截图的另一段161帧样本P95 34ms。仍存在少量载入长帧，不能把该读数说成全程无卡顿或真机/大图库性能保证；后续应继续针对首次加载和大量历史核对，保留原始 `framestats` 数据。

## 10. 来源往返修正（2026-10-09）

针对用户反馈的非首行图片返回焦点错误、组件进出不自然和底栏闪烁，完成以下修正：

- 共享动画限定为当前图片；详情相邻预加载页不再同时飞回图库。
- 分页初始数量使用完整顺序快照，返回采用实际当前页，冻结本次返回身份。
- 恢复列表位置后才判断是否需要滚动，过渡期间不同时播放列表让位。
- 每个路由持有自己的导航栏和边距，退出画廊不随详情页面改尺寸。
- 图片维持300ms边界变化；周围内容先淡出、后淡入，前景控件与同一节奏同步。
- 生成面板的共享绘制层继续遵守内容区裁切，导航栏保持在面板上方，消除越界覆盖造成的闪烁。

扩展原有设备动效测试，仍为32项JVM、18项设备测试；修复版为本地 `0.1.14-motion-fix`，原签名和code14。验收截图、录屏和安装包存放于 `.tooling/motion-fix/`。首轮旧性能采样保留为历史记录，不当作本修复版的性能保证。
