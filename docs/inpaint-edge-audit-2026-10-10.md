# 局部重绘边缘核对（2026-10-10）

用户反馈涂抹区域边缘出现线条、绳状材质，官网同类操作没有这一现象。本次发现并修正了两处实际差异。

## 原图与蒙版的尺寸变换

编辑器在原图坐标上绘制蒙版。真实样本的原图和蒙版均为 878×1280，生成画布为 832×1216。旧代码只给底图做 Cover 裁切/缩放，蒙版却按原尺寸发送；不能假定编辑器尺寸就是请求尺寸。

`ImageTransform.MaskCover` 现在与底图 Cover 使用相同的居中裁切坐标，最近邻缩放后再按 8px 网格量化。提交图始终是请求画布尺寸的黑白硬边蒙版。已有参考原图、草稿和历史记录不被改写。

## 回图还需要本地融合

官网收到 infill 回图后，使用另一份蒙版与原图做本地合成。服务器产物不能直接当成最终图保存。

2026-10-10 从官网公开静态文件核对到的管线：低分辨率蒙版填黑透明区域，方形扩张 4 格，放大 8 倍，半径 20px 的方框模糊做两轮，再以红色通道作为混合 alpha。原图 alpha 按蒙版反向衰减，回图 alpha 按蒙版衰减，最后按两者贡献合成。这里的扩张只影响回图融合，不等于扩大 API 的重绘区域，也不修改用户的“蒙版扩张”滑块。

App 的 `InpaintCompositor` 独立实现上述像素处理。普通 ZIP 和 SSE 最终图共用 `OutputImageProcessor`，先融合，再做自定义尺寸裁切，最后保存历史。未要求重绘/裁切的普通生成保持原文件字节不变。

处理逐张执行，在生成仓库的后台协程中进行；蒙版使用单通道数组、滑动窗口求和，底图/回图按行混合，位图及时回收。合成失败保留服务器原图并发送本地处理失败提示，不丢弃已生成图片、不重新发生成请求。

PNG 白名单文本元数据在重编码前读取、之后写回，体积和哈希重新计算。本次也修正了 `Generation_time` 白名单与关键字归一化不一致的问题。

## 公开来源

以下文件来自当天 `https://novelai.net/image` 的 script 引用及其 webpack worker 映射；只分析了图片处理相关函数，没有使用登录凭据或调用生成 API。

- [生成与 generateInfill 管线](https://novelai.net/_next/static/chunks/2952-8caf894fb1bb5206.js)：模块 97567，回图蒙版准备与合成调用。
- [图片辅助处理](https://novelai.net/_next/static/chunks/1601-acc34459bdce34e2.js)：模块 41622，缩放、蒙版 alpha 和原图合成。
- [像素处理 worker](https://novelai.net/_next/static/chunks/687.ce635a7067515001.js)：方形扩张、最近邻放大与方框模糊。
- [像素合成函数](https://novelai.net/_next/static/chunks/pages/_app-b1c0ffe38c343809.js)：模块 74738，蒙版衰减与 alpha 加权合成。
- [官方 Inpainting 文档](https://docs.novelai.net/en/image/inpaint/)：建议在需要修改的边缘周围留出涂抹范围；不是保证模型永不生成额外材质。

静态文件可能在官网更新时更换。旧文档关于“8px 对齐即可消除异常边缘”的解释已改为精度约定，不再把推断写成已证实原因。
