# 首页并发与生成队列

## 提交与显示

生成键保留“生成”动作，已有任务不锁住下一份草稿。每次用户点击并完成既有费用确认，冻结这一份参数、提示词与参考图；后续改词、换尺寸或移除参考图不会修改已提交的任务。每次提交都重新收起面板，任务在画廊占据最终尺寸比例的槽位。

OpenAI每次确认对应一份独立任务，原有n张参数仍是同一个请求的批量。先建立“生成中”占位，再进入三路并发位；更多任务保留占位等待，避免大量高分辨率响应同时占用内存。各请求的ID、文件、状态与失败独立。忙碌状态按全部未结束任务计数，直到最后一项结束才释放跨服务占用；期间不能更换服务或密钥。生成成功、失败或部分成功均不重发。

NovelAI首页先展开并冻结本地模板、宏、随机Seed及账号指纹，写入QUEUED和参考图索引，不编码参考图或发送请求。三光点轨道表示“排队中”，轮到任务才切换为原生成光核。队列先进先出，上一任务收尾后至少等待1000ms才执行下一项，同一时刻只有一份NAI任务进入生成链路。抽卡/对话仍按原有预约规则与首页互斥，并共用该冷却门；抽卡原有1000～2000ms间隔不被缩短。

请求单位是用户确认的一份任务，不把原有n_samples拆成多次POST，不改变计费规则。余额观察在任务取得执行位后开始，成功后的记账错误不能将已保存图片改成失败。费用公式和OpenAI估算本轮不调整。

## 失败、重建与数据

NAI失败停止尚未发送的同一轮后续项，记录“未发送”；失败任务本身按原错误保留，超时/断流仍是结果及计费不确定。重新点击属于新的明确提交，不是恢复旧项或自动重试。发送前再次核对账号和SFW设置，不能将旧账号的请求转发到新账号。

进程级ViewModel保存执行中的任务；Activity重建或导航不重复发POST。首次启动恢复由AppContainer的进程级Deferred执行一次，新任务等待其结束，避免恢复扫描误伤新任务。进程重启不恢复发送：旧QUEUED标为未发送失败，旧GENERATING按结果不确定处理。首页没有新增抽卡前台服务或唤醒锁，不保证系统结束进程后继续执行。

QUEUED是既有status TEXT字段的新值，无数据库schema变更。排队占位与执行、图片入库使用同一个生成ID。参考图行先登记保护文件，后续用UPDATE补齐Vibe缓存路径；不REPLACE生成父行，不改变历史图片或草稿字段。

## 验证

扩展既有JVM调度回归，用虚拟时间同时提交三项，断言FIFO、无重叠及前项125ms结束后再等1000ms；断言失败后旧批准代数的后续项不执行，新手动提交才可执行。画廊回归检查QUEUED切成GENERATING时槽位key不变。

扩展既有设备测试：NAI登记占位时零POST、执行ID和Seed保持不变、未发送项失败不调用API；OpenAI两项同时进入假API，一项拒绝不影响另一项保存，记录ID不同。仍为29项JVM加21项设备，不增加测试方法。原生预览直接渲染生产画廊卡片，覆盖普通和大字号下的“生成中/排队中”及轨道动效。

本轮不发布Release、不触发真实生成；设备回归只有编译，未连接设备执行。主机原生预览不替代实际点击、后台保活或手机帧率验收。

本轮结果：29项JVM单测通过（失败0、跳过0），测试预算50/50；`:app:assembleDebug`及`:app:compileDebugAndroidTestKotlin`通过，`:app:renderStatsPreview -PrenderStatsPreview=true`通过。已检查生产卡片的两张普通/大字号原生预览。OpenAI并发上限加入后的单测、Debug构建与设备编译已再次通过；本轮未更改版本或发布附件。
