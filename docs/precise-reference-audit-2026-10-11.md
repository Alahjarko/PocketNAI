# Precise Reference 相似度排查（2026-10-11）

用户反馈偏向角色形象不够像，未提供可复现的参考图与结果配对。本次通过官网公开前端代码和本地生成链路确认差异；下面的原因是代码事实，不是实际出图相似度评分。

## 已修正的差异

| 环节 | 原 App 行为 | 官网行为及本次修正 |
|---|---|---|
| Fidelity | 滑块原值直接发送到 `director_reference_secondary_strength_values` | 发送 `1 − Fidelity`；界面 1 对应请求 0，0.65 对应 0.35 |
| 小参考图 | 普通 Letterbox 限制缩放不超过 1，小图缩在大黑框内 | 等比放大或缩小到一边贴合画布，再居中补边 |
| 画布选择 | 用 1.1 比例阈值判断横、竖、方 | 在 1024×1536、1536×1024、1472×1472 中选择长宽比绝对差最小者，等距取前项 |
| 新导入的默认类型 | 仅角色 | 角色与画风；保留已有明确类型，补齐「画风」选项 |
| 描述字段 | 附带 `use_coords`、`use_order` | 使用 `caption` 和 `legacy_uc: false` |
| 缺省参数显示 | 空值显示滑块下限，实际发送模型默认值 | 界面和请求统一使用模型默认值 |

第一项直接颠倒了 Fidelity 的意义：App 默认显示 1，却提交官网 Fidelity 0 对应的值。第二项也会减少有效参考内容：256×384 的图原来仅占 1024×1536 画布面积的 1/16，修正后铺满该画布。450×500 的近方图现在选择 1472×1472，与官网一致。

## 数据兼容

- `ReferenceImage.secondaryStrength`、草稿和历史始终保存界面 Fidelity 原值。仅请求构造阶段取反，无数据库迁移，不反写旧记录。
- 普通图生图、Vibe 和其他 Letterbox 的缩放规则不变。
- 历史已补黑边的参考图不自动裁边：黑色可能属于作品，无法可靠识别原始边界。需要重新选择原图才能得到新版导入处理；已有参考的 Fidelity 请求修正立即生效。
- 本次对齐几何、类型与参数。官网缩放滤镜为 Lanczos，App 仍使用 Android 现有过滤采样；不宣称编码后像素逐字节相同。
