# 05 · 账号、计费、代理与更新

[返回架构总览](../PocketNAI-架构说明与功能拆解.md) · [数据生命周期](04-数据历史与文件生命周期.md) · [限制与验收](06-原生移植边界与验收.md)

## 1. 双认证

### 1.1 Persistent Token

默认连接方式。用户输入trim后的Token → GET `/user/data` → HTTP成功才保存加密凭据 → 更新SessionState → 进入首页。账户响应解析宽容，200但JSON无法解析仍可得到connected=true；这条接口的核心职责是验证凭据被接受，不是读取准确余额。

凭据类型为PERSISTENT_API_TOKEN或ACCOUNT_SESSION。生成链路只读取 `credentialStore.load()?.token`，不知道邮箱、密码或派生算法；类型仅用于会话提示和失效引导。

### 1.2 实验性账号登录

```text
用户邮箱和密码
  → preSalt = 密码前6个Unicode码位 + 邮箱 + novelai_data_access_key
  → BLAKE2b-128(preSalt UTF-8) 得16字节盐
  → Argon2id(password UTF-8, salt)
  → URL-safe Base64编码64字节输出，取前64字符
  → POST /user/login，JSON仅为 key
  → 从成功JSON读非空accessToken
  → GET /user/data复验
  → 保存ACCOUNT_SESSION凭据
```

Argon2参数是版本1.3、迭代2、内存 `2_000_000 / 1024 = 1953 KiB`（整数除法）、并行度1、输出64字节。不是默认库参数，不可随意写成2MiB。邮箱由调用端trim，不统一转小写。密码前缀按Unicode码位，而非UTF-16单元或Swift扩展字素簇；emoji和组合字符是跨语言一致性的重点。

派生在Dispatchers.Default运行。密码与Access Key不落盘、不写日志，登录请求发派生key而非密码。连接页在后台/离页清密码，登录finally再次清空。当前String不可保证原内存物理擦除，所以准确表述是“缩短持有时间、不持久化”，不是“绝对零残留”。

登录总调用超时60秒，响应最多64KiB，成功也必须检查accessToken为非空字符串。不自动重试、刷新Token或接管浏览器Cookie。Google等SSO账户使用PST，没有Google登录流程。

403登录映射LOGIN_VERIFICATION_REQUIRED，401为LOGIN_CREDENTIALS_INVALID；生成接口的403则是TOKEN_INVALID。登录超时REQUEST_TIMEOUT，不能提示可能扣生成费用。

源码：[Access Key派生](../../app/src/main/java/net/pocketnai/domain/auth/NovelAiAccessKeyDeriver.kt)、[认证HTTP](../../app/src/main/java/net/pocketnai/data/network/OkHttpNovelAiAuthApi.kt)、[连接状态](../../app/src/main/java/net/pocketnai/ui/connect/ConnectViewModel.kt)。

## 2. 安全存储与多账号

`KeystoreCredentialStore`用AndroidKeyStore AES-256-GCM，别名 `pocketnai_token_key`，128位认证tag；SharedPreferences `pocketnai_secure`只落密文/IV及类型、时间、长度/短hash提示。原有 `token_iv` / `token_ciphertext` 保持兼容；实际类型键是 `credential_type`，不要照旧注释写成token_type。

多账号以 `accounts_index`、`active_account_id`和每账号 `account_<id>_*` 存储；顶层凭据是当前账号镜像，旧生成代码仍从顶层读取。`ensureLegacyMigrated`将无索引的旧顶层凭据转成default账号索引，保留原密文。

| 操作 | 行为 |
|---|---|
| 添加PST | AccountAdder复验 → saveAccount → 必要时switchAccount |
| 添加登录账号 | 派生 → login → user/data复验 → 保存/切换；任一失败不继续后续网络阶段 |
| 切换 | 解密目标确认可读 → 更新顶层镜像 → SettingsViewModel清余额并强制刷新 |
| 改名 | 仅改本地显示名 |
| 删除非活跃账号 | 移除该账号索引和密文 |
| 删除活跃账号 | 尝试切到剩余账号；无剩余则clear |
| 断开连接 | 当前clear清整个凭据首选项，即全部已保存账号；历史数据库不清 |

凭据接口有多账号默认假实现，真实行为只在Keystore实现里。跨平台适配不能遗漏这些方法却仍编译成功。加载密文失败时当前clear同样可能清整个存储，而非只删坏的一条。

普通历史不按账号隔离；草稿、主题、代理、订阅覆盖均全局。切账号会清余额，但不会自动清除手动Opus覆盖。未来如果用户期望每账号配置，需要设计明确的作用域。

备份规则只显式排除pocketnai_secure；Android allowBackup=true，私有历史可能被系统备份，当前“本地存储”不代表“任何系统云备份都被禁用”。代理密码另外经SecretBox/Keystore加密；目标平台应把系统密钥和数据备份策略一起设计。

## 3. 余额是读服务器状态

`AccountBalanceRepository`状态为Unavailable、Loading(previous)、Available(balance,stale)、RefreshFailed(previous,error)。刷新失败保留旧值，不清零。余额只在内存，普通新鲜窗口5分钟；多个并发刷新共享Deferred，通过Mutex避免重复发起。

刷新触发：连接成功、回前台、用户手动、生成完成、402或结果不确定时。强制刷新绕过新鲜度，但复用在途请求。apply之前再次比对当前Token，防止旧账号响应写入新账号界面。

响应读取：

| 字段 | 含义 |
|---|---|
| trainingStepsLeft.fixedTrainingStepsLeft | 订阅Anlas |
| trainingStepsLeft.purchasedTrainingSteps | 购买Anlas |
| tier/accountType/expiresAt | 权益判定输入 |
| active/isGracePeriod | 保留原始事实，active不用于订阅判定 |
| usage.percent/isNegative/timeUntilNextPercent | V5额度原值、是否负额、下次恢复时间 |

两种Anlas必须是非负整数，不能把缺失字段当0。V5原始百分比可以有特殊范围，显示与业务判断分开。查询错误用账户读取映射器，超时REQUEST_TIMEOUT。

并发边界：`clear()`只清状态，不取消旧inFlight；切账号后的新refresh可能await旧Deferred，尽管旧apply被Token比较丢弃。当前不能保证每次切换都立刻取得新余额。余额变化计算也没有绑定完整账号会话代数，见06。

## 4. 费用是本地规则

### 4.1 权益解析

`SubscriptionStatusResolver`统一处理：accountType为B2B/SERVICE/SUPPORT/ADMIN，或expiresAt晚于现在且tier为有效付费档，即认为有订阅。tier映射0无、1Tablet、2Scroll、3Opus。手动覆盖AUTO/NONE/TABLET/SCROLL/OPUS直接替代读数，只影响本地展示与推算，不能给服务端增加权益。

### 4.2 报价上下文

`GenerateViewModel.costEstimate`组合草稿、余额、订阅覆盖。`AnlasPricingContext`包含请求画布、张数、模型、steps、订阅、V5额度、图生图/重绘strength、Precise数量、Vibe数量与未缓存数。未缓存判定和实际编码共用cacheKey。

输出四态：Free、UsesV5Allowance、EstimatedAnlas、Unknown。未知不伪造数字；缺余额不阻止用户生成。当前V5缺usage但本地具备免费条件时仍可能返回UsesV5Allowance，并非严格把所有未知权益判为Unknown。

### 4.3 本版本公式

实现版本为 `novelai-web-2026-09-14`。以下复述当前公式，未来服务价格需重新核对，不把它作为永久协议。

```text
A = max(width × height, 65536)
r = ceil(2.951823174884865e-6 × A + 5.753298233447344e-7 × A × steps)
r = r × smeaMultiplier × (V5 ? 1.5 : 1.0)
s = strength > 0 ? strength : 1.0
perImage = max(2, ceil(r × s))
baseTotal = perImage × billableImageCount
surcharge = 5 × preciseCount × sampleCount
          + 2 × max(vibeCount - 4, 0)
          + 2 × uncachedVibeCount
total = baseTotal + surcharge
```

公式支持面积≤3,145,728、steps≤50；单图结果超过140或无法报价返回未计价。当前四模型smeaMultiplier保持1.0。整数累加/乘法使用溢出饱和。不要把两个ceil合并，也不要给生成费用加0.8订阅折扣。

免费条件：有订阅且Opus，面积≤1024²，steps≤28，至少一张；V5仅当usage.isNegative为true时禁止免费名额。每批最多免一张基础费用；Precise/Vibe附加费仍在。图生图与重绘不因有底图取消免费，Characters不额外计费。

仓库约定的V4.5 Curated + Normal +23步+7.0实验组合，是曾验证账号下的操作边界，不是“任何账号、任何时间都免费”的判断式。真实调用仍需用户手动发起。

超分独立按**源图面积**报价：≤1,048,576为1；≤1,747,627为2；≤2,446,678为3；≤3,145,728为4 Anlas，超过禁用。Opus免费名额不覆盖超分。

## 5. 余额变化与流水

点击生成前只快照已有内存余额，不额外等待网络。完成后强刷余额。`ObservedBalanceChange`检查快照是否齐全、任务是否确认完成、前快照是否过旧（默认2分钟）、期间是否有余额增加，然后产出Anlas下降、V5额度变化、暂无可见变化或不确定。

同账户可能在其他设备消费/充值，服务端也可能延迟更新。因此“观察到减少10”不是本次请求具有唯一可验证账单id。

**当前流水金额来自观察差，已不是旧AGENTS描述的报价写入**：生成成功后用change的差额；Ambiguous某些情况退化为前后总额差，无法取差时可能0；生成后余额刷新失败则这条路径直接返回、不记录。超分余额缺失时仍可记0。0不能当成已证实免费。

流水只保存id、账号短指纹、操作类型、消耗、V5变化、余额后值、描述、关联id和时间。最近100条查询目前未按账号筛选，清空账单是全表操作。100是显示查询上限，DAO并未定期删除超过100条的旧数据；界面“保留最近100条”的措辞不能当作存储裁剪策略。没有从NovelAI同步完整账单，也没有账目CSV导出入口。

`AnlasLedgerRepository.record`直接调用DAO，未catch；“记账失败不影响生成”是应保留的约定，但当前实现不能完整保证。还有超分调用方把新**图片id**传入名为generationId的流水字段，以及普通生成收尾用当前编辑状态/当前凭据提示产生账目描述的边界，均列于06。

## 6. 代理链路

设置可关闭、启用公益SOCKS节点或自定义SOCKS5/HTTP。自定义需要非空host和有效port才active；否则clientFactory回直连。界面支持`host:port:user:password`格式解析，该格式不支持任意含冒号密码或IPv6表达。

公益节点来自加密assets，客户端用内置材料解密；这是防随手提取，不是抵抗专业逆向的服务端密钥管理。本文不记录节点端点、用户名、密码或派生密钥。更换凭据由维护者运行专用加密脚本，不把真实凭据写进文档。

`novelAiClient()`按当前设置选直连或代理client，因此不必重建API对象。代理client加3秒connectTimeout、quota拦截器、failover拦截器、body字节监听。GitHub检查和下载明确走直连基础client。

SOCKS认证通过全局Java Authenticator，按当前端点端口匹配，兼容Android把requestorType标SERVER的行为。HTTP代理选项存在，但AppContainer未接入OkHttp的HTTP407 proxyAuthenticator，不能保证自定义HTTP用户名/密码路径完整。

公益节点首次随机选，下次轮转；failover最多3次总尝试。重试条件是selector记录该尝试期间发生connectFailed，或请求为GET/HEAD且异常是SocketException。普通HTTP错误状态不触发这套重试；POST不是无条件可重试。

每日额度常量为750×1024²字节，统计请求/响应body，包含自定义代理流量，只有公益模式执行上限拒绝；不等于真实网络接口流量，不含所有协议开销，也不是服务商账户总量。日期在读取初始化和addTraffic时重置。当前quotaExceeded只读内存计数，跨午夜长驻且已满额可能继续拦请求，需在移植时修正或明确处理。

调试日志的约定是只记结构；`ProxyFailoverInterceptor`现有代码仍拼接截断异常message，异常可能含端点信息。新平台应按约定做字段级脱敏，不能因为存在RedactingHttpLogger就认为所有异常日志已安全。

## 7. 更新、安装与发布

`GitHubReleaseApi`匿名GET仓库releases/latest，不附NovelAI凭据和用户内容。`UpdateEvaluator`解析严格build-N正整数tag，优先找PocketNAI.apk，找不到再取.apk附件；仅按versionCode比较。

启动延迟3秒静默查；失败不打扰，手动查询显示结果。用户选稍后保存已忽略构建号，同版本不再启动弹出。下载经HTTPS写.part再rename，缓存有效APK可复用，然后通过FileProvider交系统安装器。未知来源安装权限不够时跳系统设置，之后用户再次发起安装。

签名比较使用当前安装与APK的证书SHA-256集合。明确不匹配会删除包并报UPDATE_SIGNATURE_MISMATCH；**当前读取不到签名时return true放行**，不是严格验证失败即拒绝。源码没有对包名、下载大小、最终APK内部versionCode做一套完整校验。这是重要移植边界。

发布有本地PowerShell脚本和手动workflow_dispatch两条路径：读取现有Release最大build-N+1 → 测试 → 注入PNAI_VERSION_CODE/NAME → assembleDebug →上传固定附件名 → 保留最近3个Release。当前默认本地构建为1/0.1.0，发布的是保留签名兼容性的debug APK。CI显式指定同一把签名密钥，本地不无条件覆盖debug签名配置。

最大编号+1减少平常冲突，但不是分布式编号锁；本地和云端同时读同一最大值仍可能竞争。SwiftUI与Windows应按各自分发渠道重新设计包类型、签名与安装，而不复用APK资产筛选。

## 8. 安全与责任边界

输入密码、Access Key、PST和Access Token不进日志/历史/图片/剪贴板。普通提示词可被用户明确复制，网络日志仅记方法、路径、状态和耗时，不能记含prompt的query或完整请求体。错误detail当前有保留截断服务端body的路径，不是完整白名单脱敏体系；未来如服务端回显内容，可能进入历史，见06。

没有开发者自建中转后端，但用户可选网络代理；历史留在本机，不代表系统备份关闭。把“API用途”“传输路径”“本地持久化”“系统备份”“用户主动分享”分开，才能在新平台向用户作准确说明。
