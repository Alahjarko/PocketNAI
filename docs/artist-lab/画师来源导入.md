# 导入自己的画师来源

在「抽卡 → 画师库 → 导入」选择 UTF-8 的 TXT 或 JSON。先预览新增及已有画师数量，点「加入画师库」才保存。相同标签只保留一位；已有画师的启用／移出状态、代表作、批次和收藏不被导入文件覆盖。新画师可移出或重新启用，重新打开应用后仍保留。

TXT 与 WinNAI 导出的名单兼容，每行一个 `artist: 名字`，也接受没有 `artist:` 前缀的规范标签。下划线、空格和大小写在去重时统一。空行和以 `#` 开头的说明行被忽略；不接受权重、多个逗号分隔的画师或其他提示词。

JSON 可使用画师库导出的旧版配置（schemaVersion 1）或下方新版格式。新版支持来源名称、Pixiv／X 主页与审核说明。文件最多 2 MiB、5000 位画师；单个说明最多 2000 字。JSON 不包含图片文件，新增条目不会由文件里的 assets 路径载入图片，也不会自动联网下载；已有画师的内置代表作保留。ZIP 用于导出归档，导入请选择其中的 JSON。

```json
{
  "schemaVersion": 2,
  "sourceName": "我的画师来源",
  "artists": [
    {
      "tag": "artist: mignon",
      "name": "Mignon",
      "sourceName": "",
      "profileUrl": "",
      "notes": "这是格式示例，请换成新找到的画师，并填写活动、人气、Danbooru 标签和画风的证据。"
    }
  ],
  "excluded": []
}
```

`tag` 是唯一必填的画师字段，应使用 Danbooru 的类别 1 规范标签。`name` 可填写中文或日文显示名。空的条目 `sourceName` 使用文件顶层的名称；主页仅接受 Pixiv／X／Twitter 的 HTTPS 链接。`notes` 可包含作品日期、相关链接、粉丝读数、判断理由和未验证事项。`excluded` 只设置新画师的移出状态，不会重新启用已移出的旧画师。JSON 中其他字段会被忽略，不会执行代码或发起生成。

画师库的「导出 → 供 AI 填写的来源模板」可保存这种文件。模板中的 Mignon 只是格式示例。把模板、自己的启用名单和下面的要求一起交给 AI，要求返回 UTF-8 JSON，即可保存后导入：

> 帮我寻找不在已有名单中的二次元画师。排除欧美风、写实人脸／CG 倾向、明显抽象概念画；作者须在近两年有可追溯的公开活动，且有较高人气、Danbooru 类别 1 规范标签和 Pixiv 或 X 本人账号。NSFW 创作经历不是排除理由。不要猜标签、主页、日期或粉丝数。每位画师的 notes 写明最近活动日期与原帖链接、人气读数及来源、Danbooru 链接、所看代表作和判断依据。未验证的人选单独列出，不混入已验证名单。返回 schemaVersion 2 的 JSON，所有新画师先放入 excluded，供我自行筛选后启用。

程序只校验文件结构、标签格式和主页链接，不代替外部资料核实，也不保证某个画师标签在所有 NovelAI 模型中具有相同效果。导入不登录、不签发授权、不启动抽卡。
