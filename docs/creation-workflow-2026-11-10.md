# 创作流程优化

用户批准上一轮评估的第2～7项，长回复阅读策略保持现状。本轮验收清单：

- [x] 历史选图：统一大面板，搜索、模型/收藏筛选、大图预览，保留选择和滚动位置。
- [x] 会话草稿：文字、选区、附件按会话保留；历史支持搜索、重命名与置顶。
- [x] 绘伴改词：图片详情可带图及参数进入绘伴；可编辑的改词卡，由用户应用/撤销，仅改提示词。
- [x] 交互细节：思考、高级参数、详情参数展开过渡；收藏等长表单统一开合与固定操作区。
- [x] 任务概览：真实模型、排队/生成状态和等待时间，可定位对应图片，不虚构进度。
- [x] 加载：图库按需查询筛选结果，会话列表只读摘要；完整历史、筛选语义、多选与详情顺序保留。
- [ ] 数据与设备：显式迁移、50项以内回归、Instabox构建/覆盖安装/实际界面验收、原签名正式发布。

沿用既有请求、费用、凭据、SFW与内容规则，不自动发起真实生成或聊天。RikkaHub仅作交互参考，独立实现。

## 实现与验证进度

开发分支`feat/creation-workflow`。schema 14→15仅新增会话置顶列、独立草稿表、生成记录的归一化搜索列和图片排序索引，不重建历史表。历史摘要不读取正文；图库默认查询120张，接近底部继续加载，详情顺序和全选单独查询全部匹配ID。超长检索词在后台回退精确匹配，避免SQLite表达式限额。

改词建议是独立的只读工具结果；用户可编辑和选择应用正向/排除词，应用/撤销核对对应服务与草稿内容，不生成图片，不修改模型、尺寸、Seed或参考图。草稿文字/选区/附件按会话持久化，删除或移除附件前核对全部历史和草稿的存活引用。

图片交给绘伴时先退出详情，再切换Tab；从聊天图片进入的详情则直接回到当前聊天，避免保存Tab状态时把详情页保存为画廊的返回位置。

Instabox已完成源码`3813d28d8cd3a63679d4c8aa71c56f69c81c516b`的29项JVM与21项设备回归，零失败，设备运行器报告79.625秒。扩展原有聊天流程核对草稿及附件往返、改词卡应用和撤销；生成集成流程核对普通手动编辑后不得撤销覆盖新词，迁移流程核对481张图片的查询上限、完整ID顺序和收藏条件。注册总数仍为29+21=50。

环境中断保留原始日志：Android系统Watchdog记录为AMS写入低内存管理服务时阻塞65秒，服务持续报告`epoll_wait failed (errno=22)`。原位重启`lmkd`后全量回归通过，服务保持启用，没有改应用代码规避系统异常。此前核对`/data`持久卷后曾恢复原Android容器，未创建新设备、未卸载应用或清数据。测试包证书与原沙箱安装一致。

用户补充平台规则：约120分钟强制挂起，30分钟无外部操作会挂起，内部脚本不算保活。后续构建记录阶段状态，外部定期核对，恢复后续接任务并检查设备服务，不将平台挂起或系统重启误报为应用回归。

独立离线验收入口`CreationWorkflowPreviewActivity`仅在`galleryBenchmark=true`启用：独立应用ID、无网络权限，使用2000条图片记录（复用4张本地几何图片）和2001条会话摘要检查分页、筛选、界面与返回，不进入发布包。

## 实际界面验收

- 离线数据为2000条图片记录（复用4张160×224几何图）及2001条会话摘要。首次页120条，滚动到第161条仍保持画廊路由；`silver hair`归一化查询匹配1000条。此样本验证分页和交互，不是2000张独立大图解码测量。
- 优化包完成多模型筛选、收藏条件、大图预览、选择确认、图片带白名单参数进入绘伴、原草稿及两张附件保留、标题搜索、重命名和置顶；返回画廊不再恢复到旧详情，任务概览可清除筛选并定位进行中槽位。
- 改词卡直接应用与编辑后应用均从生成面板读回内容，观察顺序为`soft evening light`→空→`gentle evening contrast`→空，核对两次撤销确实恢复原文。模型、参数与参考图保护另由既有生成集成项目验证。
- 实际检查收藏选择/新建表单与键盘下固定操作区、NAI高级参数展开/收起；1.35倍字号下选图可操作，系统边缘返回取消保留面板、完成返回聊天。强制停止测试进程后仍恢复原文字及两张附件。字号、返回动画与导航覆盖设置已恢复。
- 设备快照直接读取当前窗口，避免`uiautomator dump`等待持续动画失败后读取旧XML。验收入口的依赖与正式应用一样按进程保留，字体变化不会把聊天与生成面板绑定到不同实例；该入口及快照工具均不进入正式包。生产代码验收为`3813d28`，随后仅调整离线入口，优化包入口验收为`436df80`。
